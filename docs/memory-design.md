# 记忆设计（分阶段）

## 原则

记忆是带来源、作用域、重要性、有效期和可撤销性的事实/摘要，不是聊天记录备份。任何检索结果都可能包含过时、错误或注入内容，必须按 scope、来源和预算过滤。

## 三层模型

| 层级 | 内容与存储 | 生命周期 | 首阶段 |
| --- | --- | --- | --- |
| 工作记忆 | `player_id + npc_id + conversation_id` 三元 scope 内最近完整 user/assistant 回合；仅当前进程内存 | 最近 6 回合、128 活动 scope、idle TTL 1800 秒；服务重启后丢失 | F-004 已实现 |
| 情节摘要 | 高价值互动的结构化摘要、来源回合、置信度、冲突状态；存储方案待独立任务批准 | 可更新/撤销/过期 | 未实现，留给 R-05 单独评估 |
| 语义检索 | 通过 embedding 召回的已批准摘要；Qdrant 或其他向量库 | 需版本、删除、重建与备份 | 否，满足升级门槛后再评估 |

## 处理管线

当前 F-004 管线：输入 → 严格三元 scope → 同 scope 串行 → 读取最近完整工作记忆 → UTF-8 工程预算裁剪 → 唯一 persona system + 历史 user/assistant + 当前 user → provider 完成并严格校验 → 原子提交一个完整成功回合。当前不存在情节摘要、向量检索或数据库。

总预算固定为 8192 估算单位：请求结构开销 64、每条消息开销 16、UTF-8 正文字节，并固定预留回复 256。该工程估算不等于模型官方真实 token 统计；必须保留唯一 persona system 与当前 user，历史按最新完整回合优先选择、发送时按从旧到新排序，不允许半回合。

只有 `completed` 且公开响应验证通过的逻辑请求可以写入；degraded/local-fallback、422/502/503/504、取消、孤儿或晚到结果均不生成伪记忆。成功 replay 不追加，失败后手动 Retry 只在最终成功时写入一次。超过 128 个会话时先清理过期会话，再淘汰没有在途工作的确定性 LRU；在途满载必须 fail-closed。

未来若独立批准情节摘要，结构化记录才应包含 `memory_id`、scope、来源 trace、重要性、过期时间、版本及状态；当前任务不创建这些数据或存储。

## Qdrant 启用门槛

先由后续独立任务用固定评估集测出仅靠最近 N 轮工作记忆及已批准摘要的召回缺口；再证明语义检索能提升正确率且满足隔离、删除、备份、成本、延迟与隐私要求。F-004 维持纯内存，不引入 SQLite、Qdrant、embedding 或第二个状态真相源。
