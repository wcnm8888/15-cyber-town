# 记忆设计（分阶段）

## 原则

记忆是带来源、作用域、重要性、有效期和可撤销性的事实/摘要，不是聊天记录备份。任何检索结果都可能包含过时、错误或注入内容，必须按 scope、来源和预算过滤。

## 三层模型

| 层级 | 内容与存储 | 生命周期 | 首阶段 |
| --- | --- | --- | --- |
| 工作记忆 | 当前 `conversation_id` 最近已校验回合；进程/SQLite 可恢复 | 有轮数与 token 上限 | 是 |
| 情节摘要 | 高价值互动的结构化摘要、来源回合、置信度、冲突状态；SQLite | 可更新/撤销/过期 | 规划，先用 fixture 验证 |
| 语义检索 | 通过 embedding 召回的已批准摘要；Qdrant 或其他向量库 | 需版本、删除、重建与备份 | 否，满足升级门槛后再评估 |

## 处理管线

输入 → 作用域/安全过滤 → 选择最近工作记忆 → 候选情节/语义召回 → 去重、冲突检测和 token 裁剪 → 组装受来源标记的上下文 → 模型回复 → 审核后写入对话与候选记忆。

写入不得与模型成功强绑定：模型超时、过滤或客户端断连时不得生成伪记忆。结构化摘要应有 `memory_id`、scope、内容、来源 trace、重要性、过期时间、版本、状态（active/superseded/forgotten）。遗忘采用软删除/状态变更；不得静默物理删除审计事实。

## Qdrant 启用门槛

先用固定评估集测出仅靠最近 N 轮和结构化摘要的召回缺口；再证明语义检索能提升正确率且满足隔离、删除、备份、成本、延迟与隐私要求。否则维持 SQLite，避免过早引入第二个状态真相源。
